# Plain Markdown baseline

Participants may inspect the original sources, quote exact passages, use the shell and search, and write any durable Markdown they find useful. The initial `NOTES.md` is empty. There is no template, special syntax, reviewer coaching, or restriction on how many notes they use. The successor starts from that directory and the available original sources with the same objectives, citation requirements and budget as the treatment arm. The treatment adds the investigation binary, and its participants may also choose plain notes.

The independent baseline reviewer inspected the paired protocol and runner without seeing the pilot problems or keys. They found the shared prompts, resources, source files and handoff mechanics suitable for a strong baseline. They found two threats to fairness in the first runner: a handoff could be signaled in the same shell call as the review, and a successor could lose its chance to answer after consuming the last allowed shell call. The integrated runner now saves the pre-injection review state, requires a later turn for handoff, and keeps answer submission available after the shell limit. Both arms are directed to list the same optional tool directory and get the same per-turn caps. The scored local run uses serial assignments.

In the development rehearsal, both Qwen 3.5 9B and Gemma 4 26B made a provisional review, received the same source correction, saved the handoff, and produced all four submitted answer fields in both arms. This establishes that the notes baseline can produce a supported successor answer within the allotted resources. The rehearsal is not scored as pilot data.
