# ADR 0022 – Refusals name what the field needs, and one attempt reports every refusal

Accepted with bn-29t7; 2026-11-24. Refines plan §6.4 (machine-readable blockers and repair guidance) and the v1 error envelope. [Wire](../../crates/investigation-core/src/wire.rs) · [Schema hints](../../crates/investigation-core/src/schema_hint.rs) · [Transaction](../../crates/investigation-core/src/state.rs) · [Contract](../schema-v1.md#refusals) · [Dogfood note](../../notes/dogfood/2026-11-24-perf08.md)

**Problem.** In the PERF.08 dogfood (friction F4, F6, F7, F9, F10, F12, F13, F14), most retries came from refusals that named a path but not what the path needed. A schema mismatch said only "Field does not match the expected schema", so an agent had to read `$defs` to learn an enum's values or a nested type. Several gates gave a bare blocker code, a wrong-kind reference did not list the kinds the field accepts, and a missing case precondition had no path or read. A gate that depends on another field (`criterion_ref` for `ruled_out`, the chosen option among `compared_alternatives`, a reversal condition's link, `retrospective_ref` after a same-batch `retrospective.record`) did not name that field. A 32-operation transaction took four attempts because each attempt reported only its first refusal.

**Decision.**

1. *A schema mismatch names the expected shape.* When decoding a payload fails with the generic message, the refusal names what the schema expects at the failing path: an enum's values, a constant, the forms of a tagged or nullable value, or an object's `$defs` type with its required fields, the ones the value lacks and any it may not have. It gives one example, from the operation's example at the same pointer when there is one, else a minimal value built from the schema. `error.expected` carries `{"type", "enum" or "forms", "example"}` and the message names `$defs/TYPE in investigation schema OP`. Enum values and type names are schema facts that `investigation schema OP` already publishes, so this does not conflict with ADR 0018, which withholds only values that a read must establish.
2. *A blocker code says what to supply.* A refusal whose message was a bare code (`OBSERVATION_INTERVENTION_VARIABLE_REQUIRED`, `OBSERVATION_SELECTOR_INVALID` and the case, question and selector blockers) is now `CODE explanation`, where the explanation names the field and its shape. The code stays first, so a consumer that matches on the prefix is unaffected. `OBSERVATION_TEXT_QUOTE_NOT_FOUND` keeps the bare code, because the CLI adds its own quote hint.
3. *A wrong-kind reference lists the accepted kinds.* The message lists each accepted kind with its ID prefix and names the kind given. `error.expected` is `{"kinds": [prefix…]}` and `error.actual` is `{"kind": prefix}`.
4. *A dependent gate names the field it depends on.* `option.disposition` `ruled_out` is refused at `/criterion_ref`. A select choice whose option is not in `compared_alternatives` is refused at `/choice/option_ref`. A reversal condition without a link is refused at `/reversal_conditions/N` and names `assumption_ref`, `criterion_ref` and `comparison_ref`. A material close whose batch recorded a Retrospective it does not cite names the citation to add (`"retrospective_ref": {"client_ref": …}`) instead of a draft, and `actual` lists at most 20 material revisions. The field descriptions state each rule. The operation examples stay commit-ready templates (tests and agents fill in only the IDs), so the rules are in the descriptions rather than in a second example.
5. *A missing precondition gives its shape.* A case change without the case in the preconditions is refused at `/preconditions` (a transaction path, not an operation path), with `expected.preconditions` holding the current case reference and a summary `show` of the case as the repair. A Decision that cites a stale revision is told the current one, with a summary `show` as the repair. A stale comparison cell names the comparison, the option and criterion revisions, and `comparison.revise`.
6. *One attempt reports every refusal.* `record` (with or without `--dry-run`) checks each operation even after one is refused. A refused operation's writes are undone on the scratch state, so later operations see the state without it. The first refusal is the error. The others are in the new optional field `error.additional_errors`, each a full error detail with its own path and repair, in operation order and at most 64. An operation that cites the `client_ref` of a refused operation, or a record a refused operation also cited, is not reported when its refusal is `UNKNOWN_REFERENCE` or `REVISION_CONFLICT`, because it follows from the earlier one. An integrity failure stops the pass. The text form lists the further refusals after the first. Nothing commits while any refusal remains.
7. *The CLI keeps a repair that names another operation.* The CLI sets `repair.schema` to the refused operation for `GATE_FAILED` and `UNKNOWN_REFERENCE`. It now keeps a schema the operation set when that names a different catalog operation, the same rule bn-78gl applied to `repair.argv`. So an answered close with an open Question names `question.resolve`, and a conclusion on an unsupported absence basis names `assessment.add`. An `INVALID_INPUT` refusal of a payload field with no repair names its operation's schema. Each additional error gets the same repair.
8. *Warnings are given once per transaction.* A warning text that several operations of one transaction raise is listed once in the receipt.

**Rejected alternatives.**

- *Report only the first refusal and leave the rest to `--dry-run` loops.* This is the four-attempt behaviour the dogfood measured.
- *Return a list in place of `error`.* It would change the shape every v1 consumer reads. An additional optional field keeps existing consumers working (ADR 0007).
- *Report every operation's refusal, including dependents.* An operation that names a refused operation's `client_ref` would always add an `UNKNOWN_REFERENCE` that says nothing new.
- *Change the examples to show select choices and reversal links.* The examples are templates that commit with the IDs filled in; a select example needs option and criterion IDs the template cannot have.

**Consequences.**

- *Compatibility.* `error.additional_errors` is a new optional property of the error object (ADR 0007), absent when there is one refusal. The error schema and the `option.disposition`, `decision.propose`, `decision.supersede` and `case.close` payload schemas gain descriptions; `option.disposition`'s example lists `criterion_ref: null`. No new error code and no new enum value. Messages and paths that change: the schema mismatch (still starting "Field does not match the expected schema"), the blocker codes (still starting with the code), wrong-kind references, `/preconditions`, `/criterion_ref`, `/choice/option_ref`, `/reversal_conditions/N`, the retrospective requirement, and stale revisions. A consumer that matched an exact message must match a prefix.
- *Repairs.* Walkthroughs B, C and D now show `assessment.add` and `review.submit`, which the operations set and the CLI used to replace.
- *Cost.* A refused transaction is checked to its end. A refused operation is undone on the scratch state only.

**Tests.** Each fails without its fix (bn-29t7 report). `crates/investigation-cli/tests/refusal_messages.rs` covers rules 1 to 8 through the CLI: the materiality enum and the `StopCondition` type, the precondition, the intervention variables, the hypothesis.disposition kinds, `criterion_ref`, `compared_alternatives` and reversal links, a stale revision, a dry run with three refusals and a suppressed dependent, `question.resolve` kept, and a repeated warning given once. `drill_closure.rs` covers the uncited same-batch Retrospective, `investigation-store/tests/derivation.rs` the `strict_json` refusal, and `schema_hint::tests` the hint itself.
